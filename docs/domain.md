# 도메인 모델

## 핵심 개념

- `Resume`: 사용자의 이력서 원본과 현재 편집 상태
- `ResumeVersion`: 특정 시점의 변경 불가능한 이력서 버전
- `JobPosting`: 저장한 채용공고와 원문 스냅샷
- `MatchAnalysis`: 특정 이력서 버전과 특정 공고의 분석 결과
- `MatchCriterion`: 자격요건 또는 우대사항 하나와 그 판정 및 근거
- `ResumeSuggestion`: 공고에 맞춘 수정 제안. 원문을 직접 덮어쓰지 않는다.
- `Application`: 사용자의 지원 건
- `SubmittedResume`: 해당 지원에 실제로 제출한 이력서 스냅샷
- `ApplicationEvent`: 지원, 과제, 면접, 처우 협의 등 상태 변경 기록
- `NextAction`: 사용자가 다음에 해야 할 일과 기한

## 데이터 원칙

- 모든 사용자 소유 데이터에는 소유자를 명시하고 Supabase RLS로 다른 사용자의 접근을 차단한다.
- 공고 원문과 실제 제출본처럼 과거 사실을 증명하는 데이터는 이후 편집되는 문서와 분리한다.
- `ResumeVersion`과 `SubmittedResume`은 생성 이후 직접 수정하지 않는다. 변경은 새 버전 또는 새 스냅샷으로 남긴다.
- 분석은 사용한 `ResumeVersion`과 `JobPosting` 원문 버전을 참조하여 재현할 수 있어야 한다.
- 중요한 상태 변경은 `ApplicationEvent`처럼 감사 가능한 기록으로 남긴다.
- 날짜는 저장 시 표준 형식을 사용하고 화면에서는 한국 시간대와 로케일을 고려한다.
- DB 스키마 변경에는 마이그레이션, 사용자 소유권 기반 RLS 정책과 권한 테스트를 포함한다.

## 파일과 개인정보

- 원본 파일명을 저장 경로로 사용하지 않는다.
- 다운로드 시 로그인 사용자와 리소스 소유권을 다시 확인한다.
- 파일 원본, 추출 데이터와 편집 가능한 텍스트를 구분한다.
- 서비스 키와 서버 전용 비밀값은 클라이언트에 노출하지 않는다.
- 이력서 원문과 개인정보를 로그, 오류 메시지 또는 분석 이벤트에 불필요하게 기록하지 않는다.
